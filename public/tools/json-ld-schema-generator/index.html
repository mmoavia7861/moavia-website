Worked example: FAQPage markup

Imagine a fictional website with a help page that shows Question: “How can I contact the example team?” and Answer: “Use the contact form linked in the website footer.” Select FAQPage, enter that exact pair, then click Generate JSON-LD. The output includes a Question entry with an acceptedAnswer. This is fictional teaching content. Do not publish it on a real page unless visitors can read the matching question and answer there.

For Organization, use the real organization name, official website URL and any genuine public profiles. For Article, use the published headline, author, URL and date of publication. After generating the code, paste the script into the relevant webpage and check the result with the Schema Markup Validator for general schema correctness. Use the Google Rich Results Test to check supported Google features. Neither validator guarantees a search enhancement or ranking.

Frequently asked questions

What does “valid” mean in this generator?

It checks required form fields, URL formats and produces syntactically parseable JSON-LD. It does not validate all Schema.org semantics or guarantee Google's structured-data policy requirements.

Will FAQPage JSON-LD create a Google FAQ rich result?

No. Google retired FAQ rich results in May 2026. Schema.org still defines FAQPage as a type, but it does not enable that retired Google feature.

How can I validate the result before publishing?

Use Schema Markup Validator for general Schema.org validation and Google's Rich Results Test for types Google supports. Verify that every statement matches visible page content.

Can I use imaginary reviews, authors or organizations?

No. Publish structured data only for real information that you can substantiate on the page. The sample above is only an example of the format.
